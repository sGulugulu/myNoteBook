#### 第 1 个月：补 CUDA 基础，不求快，先求真懂

目标：

- 建立 GPU 执行模型的清晰心智模型
- 把最基本的 CUDA 编程流程跑顺

重点：

- `thread / block / grid`
	- gpu的物理模型,grid是最大单元,由多个block组成,block又由多个thread构成,排布可以定义,有一维,二维,三维之分
	一个block最多可以包含1024个thread
- `warp` 与 SIMT
	- warp由32个thread组成,SIMT是single instruction multi threads,在处理大量相同操作时高效
		- 是一个基本的执行单位,所有线程在执行时必须同步,所有线程执行相同的指令,以SIMT模型运行
		- 减少硬件开销,方便调度
		- 提高并行度,充分利用SM内的计算资源
		- 如果出现分支发散,warp会在一个时钟周期内执行所有线程路径
		- 提高内存访问效率,尽可能访问连续的内存地址,减少内存访问延迟,,如果多个线程访问不同的内存位置,可能会导致bank conflict
		- 多个warp可以并行执行,提高流水线效率
- `global memory / shared memory / register`
	- global memory 是 全局内存, 即显卡板载内存,最大,最慢
	- shared memory 是 共享内存, 在SM内部(片上), 和L1缓存共享一块(可以被不同比例划分开)
	- register 是寄存器, 被均匀分给warp的所有线程
- `coalesced access`
	- 合并访问, 把多个线程对**全局内存**的连续地址访问进行合并, 作为一个内存事务(memory transaction),是高效的内存访问请求
	- 要求 
		- 访问模式 : 
			- 连续 : 线程0、线程1、线程2……依次访问内存地址 `0, 4, 8, 12, ...`（假设每个线程访问4字节）
			- 对齐:  cuda设备的内存访问是按照32或64字节进行对齐的, 这要求线程访问的内存地址必须按照其因数大小进行对齐(4字节对齐)
			- 根据数据存储特性 : 对于1d数组,线程顺序访问,但是对于数组和张量,需要线性化之后按行访问
- `bank conflict`
	- bank: 共享内存被分成了32个bank对应warp的32thread,这三个概念都是针对翻个SM(Streaming Multiprocessor)的
	- bank conflict 是指,同一时钟周期有多个thread请求访问同一个bank.导致访存效率大幅降低, **特例**: 如果32个thread都要访问同一个bank,会有自动优化, 把数据广播给所有线程,不会冲突
	- 解决方案: 改变数据布局或访问模式
		- padding:  \[32\]\[32\] 的数组,但是声明为\[33\]\[33\] , 与32互质,可以保证没有bank conflict (缺点: 牺牲空间)
		- 改变访问模式 : 在设计算法时，尽量避免让线程ID乘以Bank数量的倍数去访问内存(swizzle)
			- swizzle 计算换时间: 通过可逆的运算操作,在硬件层面动态肉乱物理地址和bank的映射关系,动态改变每个元素的bank归属,使请求重新均匀发送到32个不同的bank上
		- 硬件加速: TMA(temsor memory accelerator) , WGMMA(Warp Group Matrix Multiply-Accumulate),MMA (Matrix Multiply-Accumulate) 指令
		- 软件层面: 交错存储(interleaving), 基于数论的解决方案(Number-Theoretic Solution),向量化内存访问 (Vectorized Memory Access)
- `occupancy`
	- 是指在 GPU 上执行一个内核（kernel）时，已分配的 线程 数量与可用的 最大线程数量 之间的比例。
	- 每个SM的资源有限(寄存器,SMEM,线程数,每个线程块的线程数),如果 线程块内的线程数过多 或者 每个线程占有的资源(寄存器,SMEM)过多 , 那么 occupancy就会下降
	- 计算工具 `nvcc --gpu-architecture=sm_60 --maxrregcount=32 my_kernel.cu` 这条命令会输出关于 **occupancy** 的详细信息，帮助你了解内核的资源使用情况。
- `synchronization`
	- 三种同步: 线程之间的同步 , 线程块之间的同步 , 流之间的同步
		- 防止多个线程同时访问相同的数据,导致数据竞争, 不一致性, 死锁
		- `__syncthreads()` 用于线程块内的同步,不会跨线程块进行同步
		- cuda没有提供跨线程块的同步机制,需要借助多个内核调用和流来间接实现同步
		- `cudaStreamSynchronize(stream)` 用来同步特定流的操作 
		- ```cpp
			cudaStream_t stream1, stream2;
			cudaStreamCreate(&stream1);
			cudaStreamCreate(&stream2);
			
			kernel1<<<1, 256, 0, stream1>>>(data);
			kernel2<<<1, 256, 0, stream2>>>(data);
			
			cudaStreamSynchronize(stream1);  // 等待 stream1 完成
			cudaStreamSynchronize(stream2);  // 等待 stream2 完成
		  ```
		- `cudaDeviceSynchronize()`是设备级的同步,可以阻塞主机线程,指导流中所有的工作都完成
	- 影响: 额外的性能开销,增加延迟,降低并行度,避免使用cudaDeviceSynchronize()

产出：

- `vector add`
	- `cudaMemcpy(d_a, h_a.data(), size, cudaMemcpyHostToDevice)` 
		- `cudaMemcpy()`的函数签名是`cudaError_t cudaMemcpy(void* dst, const void* src, size_t count, cudaMemcpyKind kind);`
		- 而`h_a.data()`是`std::vector<float>` 底层连续内存的首地址
			- .data()函数技巧: 
				- 1. `h_a 是 std::vector<float>`，而且它不是 `const `所以 `h_a.data()` 返回的是 `float*`
				- 2.`float*` 可以隐式转换成 `const float*`再进一步转换成 `const void*`
				- 相当于:  `float * -> const void *`
				- `float* p = h_a.data(); //返回指针  const void* src = p; //指针自动转成const void*  cudaMemcpy(d_a, src, size, cudaMemcpyHostToDevice);`

- `reduce`
	- `shared memory`分配: `extern __shared__ float sdata[]`
		- extern 这个关键字告诉编译器,大小是由kernel launch 时指定的, 而不是静态确定的. cuda 会在运行时根据kernel的配置动态分配这块`shared memory`
		- sdata[]不带* : 和`float * sdata`等效,且可以让编译器知道这是一个共享内存的数组,可以进行优化
